# KOMY 토론장 v3.3

## v3.3 재개 시 원문 오류 피드백

인용 검사에 실패한 단계를 사용자가 재개하면, 직전 제외 응답과 잘못된 인용 위치·원문 ID·길이·존재 여부를 함께 전달해 재검토한다. 검사 기준은 완화하지 않고, 제외 응답을 완료로 승격하지 않는다. 자동 재호출은 없으며 기존 9회 한도를 유지한다. 기존 완료 단계는 다시 호출하지 않는다. 실제 모델이 수정에 성공하는지는 별도 확인이 필요하다.

## v3.1 목록 조회 화면 수정

회사별 조회 중·성공 건수·실패 이유·빈 목록 상태를 화면에 유지한다. 처리 중 버튼을 잠그고 회사별 조회 시간을 전체 20초로 제한한다. 한 회사가 실패해도 다른 회사 목록을 조회한다.
조회 실패 시 모델 선택 상자 아래의 직접 입력 칸에 기존에 성공했던 모델 ID를 넣고 저장할 수 있다. 직접 입력값이 목록 선택보다 우선한다.
이 수정은 실제 계정의 목록 조회 성공을 확인한 결과가 아니라 진행/실패 관찰과 대체 입력을 보완한 것이다.

## 업데이트와 실행

1. 기존 검은 실행 창을 닫는다. 안전을 위해 기존 토론장 폴더 전체를 복사해 백업한다.
2. ZIP 내용을 기존 `Start-KOMY.cmd`가 있는 폴더에 덮어쓴다. 기존 폴더와 `.local` 폴더를 삭제하지 않는다. ZIP에는 개인 기록·키·DB가 없다.
3. `Start-KOMY.cmd`를 더블클릭한다. 브라우저가 안 열리면 http://127.0.0.1:3217 로 접속한다. 실행 창은 켜 둔다.
4. 첫 실행 시 기존 DB가 있으면 `.local/backups`에 별도 사본을 만든다. 백업 실패 시 시작을 중단하며, 기존 기록을 삭제하지 않는다.

Node.js 24 이상과 Windows PowerShell이 필요하다. 외부 패키지나 새 도구 설치는 하지 않는다.

## AI 연결 — 키 보관과 모델 선택

- 왼쪽 **AI 연결**에서 두 API 키를 입력한다.
- **이 PC에 암호화 보관**을 선택하면 Windows DPAPI의 CurrentUser로 보호해 `.local/credentials.dpapi`에 저장한다. 다음 실행 시 같은 Windows 사용자 계정에서 복원한다.
- 체크하지 않으면 메모리에만 적용하고 이 앱의 기존 보관 키를 지운다.
- 저장된 키는 입력 칸에 다시 표시하지 않는다. **등록됨**을 확인하고 빈 칸으로 저장하면 기존 키를 유지한다.
- **키 적용 후 모델 목록 불러오기**를 누른다. 회사별 실제 API에서 목록을 조회한다. 생성 요청을 보내지는 않는다.
- 모델을 선택한 뒤 **키·선택 모델 저장**을 누른다. 기존에 사용하던 모델도 현재 선택값으로 유지된다.
- 목록 조회 성공은 실제 응답 생성, 모델 호환성, 잔액까지 확인했다는 뜻이 아니다. OpenAI는 이름으로 대화용 후보를 거르므로 목록의 모든 모델이 Responses에 호환된다고 보장하지 않는다.
- 보관 키 삭제는 이 앱의 복사본과 메모리 설정만 지운다. 회사 계정의 API 키 자체를 폐기하지 않는다.
- 키는 채팅·자료·의견란에 넣지 않는다. 브라우저의 비밀번호 저장은 선택하지 않는다.

DPAPI는 평문 파일 저장을 피하고 다른 Windows 계정의 복원을 제한한다. 같은 Windows 사용자 권한으로 동작하는 프로그램이나 감염된 PC로부터 키를 완전히 격리하는 방식은 아니다. 만료된 키는 다시 입력해야 한다.

## 기획 자료와 큰 방향

새 **기획 자료** 메뉴에는 기존 대화 요구사항 정리, 해피 작업환경 설계서 v1, 우똥이 ERP 검토 보고서가 기본 등록된다. 모두 참조·검토 대상이며 승인된 업무 규칙으로 자동 취급하지 않는다.
자료 선택을 바꾸거나 MD/TXT/JSON 파일 또는 붙여넣기로 추가할 수 있다. 파일당 2만 자, 실행 전체 스냅샷은 6만 자까지다. 넘으면 자르지 않고 시작을 차단한다. PDF 직접 추출은 지원하지 않는다.
새 실행은 선택 자료, 방향, 해당 안건 의견·결정을 고정 사본과 해시로 보관한다. 자료가 바뀌어도 진행 중 실행의 사본은 바뀌지 않는다.
기존 채팅 기억이나 파일이 자동으로 모두 전달되지는 않는다. 보내려는 자료를 시작 화면에서 확인한다.

## 새 토론은 6단계

1. Claude 독립 초안
2. GPT 독립 초안 — Claude 초안을 보지 않는다.
3. Claude 원문 근거 검토
4. GPT 원문 근거 검토 — Claude 검토 결과를 보지 않는다.
5. GPT 근거 포함 결론
6. Claude 최종 요약 충실성 점검

검토와 결론은 JSON 구조로 받는다. 인용 ID와 8자 이상의 실제 원문 연속 인용이 일치하는지 검사한다. 이견에는 양측 발언의 인용이 필요하다. 인용 불일치나 형식 오류는 단계를 완료 처리하지 않는다.
마지막 AI 점검이 revise이면 **수정 필요**로 남고 해당 실행에 연결한 승인을 차단한다. 자동으로 내용을 수정하거나 재호출하지 않는다. 최신 자료와 지적 사항을 보완한 새 토론이 필요하다.
pass여도 사람 승인 전 제안이다. 인용의 의미에 대한 AI 점검은 완전하지 않으며 실제 계산·권한 시험·외부 사실 확인을 대신하지 않는다.
기존 v2 실행은 기존 5단계·8회 한도를 유지하며 중단 단계부터 재개할 수 있다. 새 실행은 6단계·최대 9회 시도다. 기록·자료 변경 후에는 오래된 실행에 새 승인을 연결할 수 없다.

## 비용·중단·기록

정상 새 토론 6회, 재개 포함 최대 9회 시도. 자동 재시도 없음. 호출당 120초, 실행 구간 15분 제한이다.
응답 출력 상한은 Claude 4,096 / OpenAI 6,000토큰이다. 금액 단위의 강제 지출 상한은 없다. API 계정에서도 한도를 설정한다.
선택한 자료를 매 호출에 함께 보내므로 짧은 안건만 보냈던 이전 버전보다 입력 비용이 커질 수 있다. 시간 초과·중단된 호출도 과금됐을 수 있다.
서버 종료 시 실행은 중단 상태가 되며 자동 재개하지 않는다. 완료한 응답은 재호출하지 않는다.
기록은 `.local/council.db`, 백업은 `.local/backups`, 암호화 키는 `.local/credentials.dpapi`에 있다. 업데이트 시 `.local`을 유지한다.
내보내기 JSON은 자료와 실행 기록을 포함하고 연결 키는 포함하지 않는다. 사용자 작성 자료에 직접 넣은 민감정보까지 자동 제거해 주는 기능은 없다.

## 검증 범위와 한계

실제 SQLite 기반 토론 상태·중단/재개·옛 버전 기록 호환·인용 검사·수정 필요 시 승인 차단·자료 고정·시드 중복 방지·설정 API·CSRF 검사·모델 목록 모의 응답을 테스트한다.
실제 Windows DPAPI로 가짜 키를 암호화하고, 새 KeyVault 인스턴스에서 복원하며, 저장 파일에 평문이 없는지 확인했다.
이 환경에서 실제 API 키를 사용한 v3 토론과 모델 목록 조회는 실행하지 않았다. 기존 v2 API 토론 성공은 사용자가 제공한 결과로 확인했으나 v3 실서비스 성공을 대신하지 않는다.
브라우저 자동화와 로컬 HTTP 통신이 환경에서 막혀 실제 화면 클릭·HTTP 통합 검증은 미완료다. 예외 상황과 원문 의미 검토에는 한계가 있다.
코딩 실행·GitHub 연동·NAS/운영 DB 접근·야간 예약·온라인 배포는 아직 연결하지 않았다. 로컬 호스트만 사용하고 포트를 외부에 공개하지 않는다.

### v3.3 인용 안정화
AI는 원문 구절 ID를 선택하고 서버가 해당 원문을 직접 붙입니다. 존재하지 않는 ID와 출처 불일치는 차단합니다. 인용 존재 검사는 의미의 정확성을 보증하지 않으며 최종 의미 검토와 사용자 승인은 유지합니다. 기존 완료 단계는 보존되므로 실패한 단계부터 수동 재개하세요. 업데이트할 때 기존 .local 폴더를 지우지 마세요.


### v3.4 아침 검토 요약
권한 안건에 쉬운 결정 카드 3개(기본 추천과 영향)를 표시하고 세부 근거는 접어 둡니다. 기본 추천은 토론 합의가 아니며 실제 승인·권한 변경을 실행하지 않습니다. 기존 기록에도 적용됩니다. 결론 작성 지시에 한도 중단·보고, 독립 검산, 테스트 보호 시험과 필요한 사람 결정 항목을 보강했습니다. 이는 앞으로 생성하는 결론에 적용되며 기존 결론을 수정한 것은 아닙니다.


### v3.5 결론 보완·재점검
수정 필요인 원래 토론에서 추가 API 과금 안내를 확인하고 보완 버튼을 누릅니다. 기존 토론은 보존하고 앞 4단계를 복사한 별도 보완 기록에서 GPT 결론 수정 → Claude 점검을 실행합니다. 보완 기록은 실패 포함 최대 2회 시도이며 자동 재시도는 없습니다. 원래 토론당 보완 기록은 하나만 생성할 수 있습니다. 자료 변경 후에는 보완할 수 없고 새 토론이 필요합니다. 점검 통과 후에도 사용자 승인 전이며 자동 코딩은 연결 전입니다.


### v3.6 누락 방지와 이어서 보완
필요 시험과 사람 결정 항목은 최대 24개로 확장합니다. 실제 반대 의견과 한쪽에만 있는 제안을 구분하는 missing 필드를 추가하고, 신규 시험 문장은 미실행 계획으로 명시하도록 요청합니다. 이는 AI 의미 판단의 완벽함을 보증하지 않습니다. 기존 v3.5 보완 기록에서도 이어서 보완할 수 있습니다. 한 차례당 실패 포함 2회 시도, 전체 3차례까지이며 매번 명시적 실행이 필요합니다. 원래 기록과 이전 보완 기록은 보존합니다. 이미 쓴 호출 한도를 초기화하지 않으며 새 보완 차례의 별도 상한으로 기록합니다.


### v3.7 두 항목 지정 수정
이번에 전달받은 권한 안건에서 반복된 두 문구만 대상으로 합니다. 최신 기록의 수정 초안 만들기는 API 호출 없이 원문 일치 확인 후 중복 누락 항목 삭제와 계약 표현 교체를 적용합니다. 원래 기록과 변경 전후·원문 해시는 보존하며 수정 결과는 별도 correction_draft 상태입니다. 다른 문구나 중복 대상에는 적용하지 않습니다. 재점검은 명시적으로 실행하며 Claude 1회 시도(실패 포함)로 제한합니다. 자동 승인이나 3차례 재작성 한도 초기화는 없습니다. 실제 시험·운영 반영은 연결 전입니다.


### v3.8 원문 대조와 판단 보류
후속 지정 수정안은 승인 대상과 미정인 구체 값을 분리하고, 원문에 없는 저장소 규칙 선택지를 제거합니다. 실데이터는 양쪽 원문의 범위 차이를 기록하되 명시되지 않은 반대 의사를 추정하지 않습니다. 수정한 오류, 점검 의견이 엇갈린 부분, 사용자 결정 제안을 나누어 보여 줍니다. 이는 우똥이의 대조 의견이며 AI 점검 통과를 대신하지 않습니다. 수정 초안은 무료 로컬 작업이고 별도 재점검은 선택적으로 1회 실행할 수 있습니다. 기존 결과나 승인 조건을 바꾸지 않습니다.


### v4.0 프로젝트 작업 공간
왼쪽 프로젝트 선택에서 AI 작업장, KOMY 시스템, ERP, 영어 선생님, AI 비서 자비스를 선택합니다. 프로젝트 관리에서 사용자 프로젝트도 추가할 수 있습니다. 기존 projectId 없는 기록과 기본 6개 안건, 기본 자료는 AI 작업장에 그대로 표시됩니다. 원본 이벤트·토론 결과를 다시 쓰거나 삭제하지 않습니다. 새 프로젝트는 빈 안건 목록으로 시작하며 + 첫 안건 등록으로 주제를 추가합니다. 방향·자료·의견·결정·토론 입력과 출력은 선택 프로젝트로 구분합니다. AI API 키와 모델 설정은 이 PC의 공통 설정입니다. 이것은 단일 사용자 앱의 데이터 구분이며 서로 다른 사용자의 보안 격리 경계는 아닙니다.

프로젝트마다 해피·우똥이 역할을 안내하지만 상시 실행되는 코딩 봇, 자동 작업 분배, AI의 자동 결정 요청 등록은 아직 연결하지 않았습니다. 현재는 사람이 프로젝트별 안건을 등록하고 토론을 시작합니다. 동시 토론은 전체 앱에서 한 개만 가능합니다. 내보내기는 선택 프로젝트의 기록만 포함합니다. 승인·보완을 위한 자료 변경 감지는 프로젝트별 버전을 사용합니다. 다른 프로젝트에 기록을 추가해도 이 프로젝트의 결과를 무효화하지 않습니다.


### v4.1 최신 글과 입력 영역
토론·의견·결정을 날짜순으로 모으고 최신 글 하나를 강조합니다. 이전 기록은 날짜와 시간, 상태가 표시된 접힌 목록에서 열 수 있습니다. 의견·결정 입력폼은 최신 글 바로 아래에 탭으로 배치합니다. 기존 저장과 승인 조건은 유지하며 의견 저장만으로 AI를 호출하지 않습니다. 새 AI 토론 설정과 안건 배경, 인용 근거는 별도로 접어 둡니다. 최신 토론은 실행 시작 시간을 기준으로 정렬하며 기존 실행의 진행 갱신은 순서를 바꾸지 않습니다.


### v4.2 첫 실행 연결 · 고정 예제
안건의 최신 글 아래에서 이 안건을 작업장 실증에 연결을 펼쳐 가상 재고 실증 작업을 등록합니다. 제작·시험 메뉴에서 조건을 확인하고 실행하면 포함된 고정 예제를 .local/jobs의 작업별 폴더에 복사하고 워커에서 가상 거래 시험을 실제 수행합니다. 결과는 5개 검사와 코드 SHA256, 고정 시드로 저장되며 해당 프로젝트 내보내기에 포함됩니다. 검증한 예제 파일도 내려받을 수 있습니다. 한 안건당 한 번, 최대 15초, API 호출 0회입니다. 실패와 재시작 중단을 자동 재실행하지 않습니다.

이 기능은 안건의 자유로운 요구를 AI가 구현하는 자동 코딩이 아닙니다. 고정 예제에만 적용하며 사용자 입력을 코드나 셸 명령으로 실행하지 않습니다. 회사 코드, 운영 DB, 금액 계산, 동시 출고 경쟁, DB 장애는 검증하지 않습니다. 결과 통과는 예제 시험 통과·사람 검토 전으로 표시하며 기존 안건의 승인이나 토론 점검 통과를 대신하지 않습니다.


### v4.3 AI 규칙 작성·독립 리뷰·실행 시험
안건의 작업장 실증 연결에서 AI 재고 규칙 제작을 등록할 수 있습니다. 실제 실행 전 두 회사 API 전송과 최대 2회 과금을 확인합니다. 작업 제목과 고정된 가상 재고 계약만 전달하며 프로젝트 전체 자료나 회사 코드, API 키를 프롬프트에 포함하지 않습니다. 해피가 JSON 계산 규칙을 만들고, 허용 변수·덧셈·뺄셈·비교·논리곱만 검증한 컴파일러가 JavaScript로 변환합니다. AI의 코드 문자열·명령·파일 경로는 실행하지 않습니다. 우똥이는 생성된 코드와 규칙을 독립 리뷰하며 수정 판정이면 실행 전 멈춥니다.

리뷰 통과 후 생성된 코드로 가상 거래 시험을 실제 실행합니다. 리뷰와 시험의 코드 해시가 일치해야 합니다. 테스트·정답 사례·컴파일러는 AI 작업자가 바꾸지 못합니다. 작성 1회·리뷰 1회, 호출당 최대 120초, 실행 시험 최대 15초이며 자동 재시도는 없습니다. API 비용은 각 계정에 발생합니다. 범용 코드 작성, 회사 코드 수정, 금액 계산, 동시성·DB 장애, 야간 예약·자동 수정 반복은 아직 연결 전입니다. AI 합의와 예제 통과는 ERP 정확성 인증이나 운영 적용 승인이 아닙니다.
