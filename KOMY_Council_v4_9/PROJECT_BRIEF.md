# KOMY 자동 개발 환경 — 션오빠의 방향과 검토 기준

상태: 기존 대화에서 정리한 요구사항과 우똥이의 검토 제안. 승인된 업무 규칙으로 취급하지 않는다.

## 션오빠가 요청한 목표

션오빠는 큰 방향을 지시하고 중요한 내용만 확인한다. 코드를 채팅 사이에서 옮겨 붙이거나 AI 의견을 전달하는 일을 줄인다.
토론장에서 안건을 제시하면 AI가 기획을 논의하고, 확정된 작업을 제작·검증·수정으로 이어가도록 만든다. 밤에도 승인된 범위의 작업을 진행하는 것이 목표다.
ERP의 계산 정확성이 중요하다. 자동 등록·계산·예외 거래를 반복 시험하고, 문제를 수정하고 재검사한 증거를 남겨야 한다. 반복 횟수나 AI 합의만으로 완벽함을 주장하지 않는다.

## 현재 완료 범위와 한계

현재 토론장은 로컬 PC의 Node/SQLite 앱이다. Claude/OpenAI API로 토론하고 기록한다. 구독 채팅의 기억은 자동 전달되지 않는다.
코딩 실행, NAS·운영 DB 접근, GitHub 작업 분배, 자동 배포, 야간 예약, 외부 검색과 계산 시험은 아직 연결하지 않았다.
이 자료만으로 실제 KOMY 권한·계산 규칙·배포 구성을 확인했다고 주장하면 안 된다.

## 작업환경 설계서 v1을 검토할 때의 제안

- 예약 실행과 매니저 기능을 구분한다. 매니저에는 작업 상태 저장·중단·재개·중복 방지·시간/호출 한도가 필요하다.
- 제작 → 자동 시험 → 독립 리뷰 → 수정 → 재시험을 연결한다. 리뷰를 사람이 다시 전달하는 방식은 최종 목표에 맞지 않는다.
- 승인된 작업 목록과 완료 조건 안에서 진행한다. 목표·범위·업무 계산 정책·지출 한도·운영 반영 변경은 따로 결정한다.
- 가상 데이터만 쓰는 격리 개발·시험 환경에서는 승인 범위 내 자동 수정·시험을 허용하는 방향을 검토한다.
- 계산 규칙, 정답 사례, 필수 검사, 승인 정책 변경을 코드 작업자에게 무제한 허용하지 않는다. 문서에 금지한다고만 쓰지 말고 권한으로 집행한다.
- 결과는 검증한 코드 버전에 묶는다. 검증 후 변경·병합되면 필요한 검사를 다시 수행한다.
- 자동화 환경의 비용·시간·재시도 상한과 아침 보고 방식을 정한다. 요금제나 특정 도구 채택은 실제 사용량과 지원 기능을 확인한 뒤 결정한다.

## ERP 파일럿 범위

한 품목군의 읽기 전용 재고·출고 파일럿을 먼저 검토한다. Seaover와 같은 기준 시각·거래 범위로 대사하고 차이는 원거래와 업무 규칙으로 판정한다.
첫 자동 개발 실증 예시는 가상 입고 → 예약 → 부분출고 → 취소 → 잔여재고 확인이다.
금액·수량 정밀도, 반올림 시점, 배부 잔액, 마감 후 정정 규칙은 사람이 확정한 정답 사례가 필요하다.
독립 검산, 무작위 거래 순서, 마지막 재고의 동시 출고, 중복 요청, 저장 도중 장애 등도 시험해야 한다.
독립 검산기는 본 계산 함수를 그대로 재사용하지 않는다. 전체 ERP를 두 벌 만들지 않고 핵심 계산부터 대조한다.

## 토론의 품질 기준

첫 의견은 서로 보지 않고 낸다. 이후 원문을 근거로 비교하고 반론을 만든다. 동의하는데 억지로 이견을 만들지 않는다.
제공 자료에 쓰여 있는 내용, AI 제안, 미확인 가정, 미실행 시험, 사람의 결정 사항을 구분한다.
AI 공통 의견은 실제 검증 증거가 아니다. 최종 요약은 실제 발언과 일치하는지 다시 점검한다.
합의가 없으면 이유와 선택지의 영향을 기록한다. AI가 오빠 대신 승인한 것으로 처리하지 않는다.

## 지금 논의해서 결정할 사항

자동 처리 허용 목록, 사람이 결정할 변경, 구체 집행 지점, 시험 항목, 첫 실행 과제, 시간·호출·비용 제한을 실행 가능한 형태로 제안한다.
검토만 반복해 개발이 막히지 않도록 작은 실증을 제안한다. 다만 실제 구현 전인 통제를 이미 작동한다고 표현하지 않는다.
