# 코미시스템 AI 에이전트 작업환경 설계서 v1

Nov 7, 2026 · @SEAN

## 1. 요약

션오빠가 코드를 복사해 붙이던 일을 없애고, AI가 밤새 만들고 검증하며 사람은 규칙과 최종 반영만 승인하는 구조로 바꿉니다.

|  | 지금 | 바뀐 후 |
| --- | --- | --- |
| 코드 작성 | 해피가 채팅으로 제시 | 해피(Claude Code)가 클라우드에서 직접 작성하고 PR 생성 |
| 코드 반영 | 션오빠가 SSH로 붙여 넣기 | GitHub에서 승인 클릭 후 배포 |
| 검토 | 우똥이에게 수동으로 전달 | 우똥이(Codex)가 모든 PR을 자동 리뷰 |
| 검증 | 수동 확인 | 자동 테스트와 회계 검증이 PR마다 실행 |
| 작업 시간 | 션오빠가 깨어 있을 때만 | 밤사이 예약 작업으로 계속 진행 |
| 션오빠의 일 | 방향, 승인, 코드 입력 | 방향, **계산 규칙과 정답 사례 확정**, 최종 승인 |

핵심 원칙은 세 가지입니다.

1. **사람은 규칙을, AI는 구현을.** 회계·원가 규칙은 AI가 지어내지 않습니다.
2. **운영에는 사람 승인 없이 아무것도 들어가지 않습니다.** main 병합과 운영 배포는 항상 션오빠가 합니다.
3. **처음 몇 주는 느리다.** 공장 라인을 깔는 기간이며, 그 뒤에 속도가 납니다.

## 2. 역할 구조와 작업 흐름

밤에는 매니저가 작업을 나눠 작업자들에게 맡기고, 모든 결과는 자동 검증과 우똥이 리뷰를 통과해야 보고서에 올라갑니다. 션오빠는 아침에 확인하고 승인합니다.

&#91;embedded content: 작업 흐름 · 밤에는 AI가, 낮에는 션오빠가\]

| 역할 | 누가 | 하는 일 |
| --- | --- | --- |
| 최종 결정자 | 션오빠 | 방향 지시, 계산 규칙과 정답 사례 확정, 할 일 등록, main 병합과 운영 배포 승인 |
| 매니저 | Claude Code 프로젝트 + 야간 예약 작업 | 할 일을 작은 작업으로 나눠 분배, 실패 시 재시도, 아침 보고서 작성 |
| 작업자 | Claude Code 클라우드 세션 여러 개 | 기능과 테스트 작성, 작업마다 별도 브랜치로 PR 생성 |
| 자동 검증 | GitHub Actions | PR마다 전체 테스트와 회계 검증 실행, 매일 밤 무작위 시뮬레이션 |
| 교차 리뷰 | 우똥이 (Codex 코드 리뷰) | 모든 PR 자동 리뷰, 독립 검산기 작성. 다른 모델이 보면 다른 실수가 잡힘 |

**아침 풍경 예시**: "어젯밤 PR 4개 완성. 3개는 테스트와 우똥이 리뷰 통과, 1개는 원가 배부 규칙이 애매해 질문 남김." 션오빠는 질문에 답하고 통과한 PR을 승인하면 끝입니다.

## 3. 승인 단계와 금지 사항

돈과 운영에 닿는 것은 모두 션오빠 승인이고, 작업 브랜치 안의 일은 AI끼리 처리합니다.

| 단계 | 대상 | 판단자 |
| --- | --- | --- |
| AI끼리 자동 | 테스트 작성, 리팩터링, 문서, 작업 브랜치 안 수정, 리뷰 지적 반영, 실패 작업 재시도 | 매니저 |
| 션오빠 승인 | main 병합, 테스트·운영 서버 배포, DB 구조 변경, 계산 규칙 변경, 외부 연동과 비밀키, 새 도구 도입 | 션오빠 |
| 절대 금지 | 에이전트의 NAS·운영 서버·운영 DB 접근, 실제 회사 데이터 사용(가린 샘플만 허용), 돈이 움직이는 모든 동작, 테스트 삭제나 기준 완화로 통과시키기 | 규칙으로 차단 |

**기술적 잠금장치**

- main 브랜치 보호: AI가 우회할 수 없는 GitHub 브랜치 규칙. 테스트 통과와 션오빠 승인이 있어야 병합
- 클라우드 작업 환경의 네트워크는 허용 목록만. NAS 주소·SSH 정보는 에이전트에게 주지 않음
- 배포는 NAS가 GitHub에서 승인된 버전을 가져오는 방식. 에이전트가 NAS에 밀어 넣지 않음
- 테스트 파일과 회계 기준 데이터 변경은 별도 표시되어 션오빠 승인 필수 ("테스트를 고쳐서 통과" 방지)
- 처음 몇 번의 야간 작업은 션오빠가 직접 확인한 뒤 무인 운영으로 전환

## 4. ERP 계산 검증 체계

AI가 수천 번 돌려도 규칙 자체가 틀리면 테스트도 틀린 것을 통과시킵니다. 그래서 정확성은 다섯 겹으로 쌓고, 하나라도 실패하면 병합하지 않습니다.

| 겹 | 방법 | 누가 | 언제 |
| --- | --- | --- | --- |
| 1. 규칙 명세 | 계산 규칙과 정답 사례를 문서로 확정 (예: 늦게 확정된 부대비용 처리, 반올림) | 션오빠 (필요하면 세무사) | 기능 개발 전 |
| 2. 불변 조건 테스트 | 깨지면 무조건 버그인 조건을 코드로 검사 | 해피가 작성, 우똥이가 검토 | PR마다 |
| 3. 무작위 시뮬레이션 | 매입·부분출고·반품·정정·비용추가를 무작위 순서로 수천 건 넣고 불변 조건 확인 | CI | 매일 밤 |
| 4. 독립 구현 대조 | 같은 규칙으로 따로 만든 검산기와 결과 비교, 1원만 달라도 중단 | 본 코드는 해피, 검산기는 우똥이 | PR마다 |
| 5. 실제 데이터 대사 | Seaover 내보내기(민감정보 가림)를 정답지로 같은 결과인지 확인 | CI + 션오빠 확인 | 기능 완성 시, 병행 기간 매월 |

**불변 조건 예시**

- 전표마다 차변 합계 = 대변 합계
- 로트별 입고 − 출고 ± 조정 = 현재 재고, 재고는 음수가 되지 않음
- 거래처별 전일 잔액 + 발생 − 결제 = 현재 잔액
- 배부된 비용의 합 = 총비용 (원 단위 차이는 정해진 규칙대로 한 곳에 반영)
- 마감된 기간의 숫자는 역분개 없이 바뀌지 않음
- 같은 자료를 두 번 수집해도 결과가 같음 (이중 반영 없음)

**테스트가 버그를 정말 잡는지도 검사합니다.** 다른 에이전트가 계산 코드에 일부러 작은 오류를 넣었을 때 테스트가 실패하는지 확인하는 방식(변이 테스트)입니다. 통과해 버리는 테스트는 약한 테스트로 보고 보강합니다.

**기능 완성 판정**: 다섯 겹을 모두 통과하고, 실제 데이터 대사에서 설명되지 않는 차이가 0건이며, 션오빠가 승인하면 운영에 반영합니다. 그다음 기능도 같은 방식으로 만듭니다.

## 5. 도구와 요금제

해피는 Claude Max로 올리고, 우똥이는 ChatGPT Plus를 유지합니다. 합계 약 월 $120(현재 대비 약 $80 증가)이며, 한 달 사용량을 보고 조정합니다.

| 역할 | 도구 | 요금제 | 비고 |
| --- | --- | --- | --- |
| 매니저·작업자 | Claude Code (클라우드 세션, 프로젝트, 예약 작업) | [Claude Max](https://claude.com/pricing) 월 $100 | Pro의 5배 사용량. 대화와 Claude Code가 같은 한도를 공유. 부족하면 Ultra(월 $200) 검토 |
| 교차 리뷰 | Codex GitHub 코드 리뷰 | ChatGPT Plus 월 $20 | 자동 리뷰 포함. 리뷰가 자주 막히면 Pro(월 $100) 검토 |
| 자동 검증 | GitHub Actions | 무료 범위 내 시작 | 비공개 저장소 무료 실행 시간 초과 시 과금 가능, 별도 확인 필요 |
| 저장소·할 일 목록 | GitHub 비공개 저장소, Issues | 무료 | 자비스와 같은 komysean 계정 |
| (보류) | Grok Build | — | 초기 베타. 구조 안정 후 세 번째 리뷰어로 검토 |

- 낮에 해피와 길게 대화하면 밤 작업 몹이 줄어듭니다. 야간 작업량은 주간 한도를 보며 조절합니다.
- 코드는 Anthropic·OpenAI 클라우드를 거칩니다. 코드는 괜찮지만 회사 데이터는 가린 샘플만 올립니다.

## 6. 전환 순서와 준비물

약 2\~3주의 준비 후 첫 야간 작업을 돌리고, 그다음 재고·출고 파일럿을 이 방식으로 만듭니다.

1. **코미시스템을 GitHub 비공개 저장소로 이전** — 현재 운영 코드(server.js, index.html)를 첫 커밋으로. 비밀번호·키는 코드에서 빼서 환경변수로 분리. 모든 자동화의 전제 조건
2. **main 브랜치 보호 + GitHub Actions 기본 틀** — 서버가 뜨는지, 기존 API가 동작하는지 확인하는 최소 테스트부터
3. **규칙 문서 작성** — CLAUDE.md(해피용), AGENTS.md(우똥이용). 백업, 테스트 우선, 금지 사항, 코드 스타일
4. **클라우드 환경 설정** — Claude GitHub App 설치, 클라우드 환경의 네트워크는 허용 목록만
5. **우똥이 자동 리뷰 연결** — 저장소에 Codex 코드 리뷰 켜기
6. **NAS 배포 방식 변경** — 승인된 버전만 NAS가 가져가는 구조. 배포 전 자동 백업 유지
7. **첫 야간 작업 (감시 모드)** — 작은 과제(예: 기존 재고 API 테스트 작성). 션오빠가 다음 날 결과를 확인
8. **무인 운영 전환** — 몇 번 문제가 없으면 범위를 넓힘
9. **재고·출고 파일럿을 이 방식으로 개발** — v4.1 전략의 첫 과제

참고: Claude를 Max로 올리는 것은 1번 작업과 함께 하면 됩니다. 준비 작업도 사용량이 많습니다.

## 7. 위험과 대응

| 위험 | 예시 | 대응 |
| --- | --- | --- |
| 에이전트 폭주 | 밤새 엉뚱한 방향으로 큰 변경을 만듦 | 작업 단위를 작게, 하룻밤 작업 수 제한, 아침 보고서에 변경 규모 표시 |
| 테스트 조작 | 통과를 위해 테스트를 약하게 고침 | 테스트·기준 데이터 변경은 션오빠 승인 필수, 변이 테스트 |
| 두 AI의 같은 실수 | 규칙을 같은 방향으로 오해 | 정답 사례는 사람이 제공, Seaover 실제 데이터 대사 |
| 사용량 소진 | 주중에 한도 도달로 작업 중단 | 야간 작업량 조절, 필요하면 요금제 상향 |
| 보안 | 비밀번호·회사 데이터가 코드나 클라우드에 노출 | 비밀값은 환경변수, 가린 샘플만, 에이전트는 NAS 접근 불가 |
| 션오빠가 병목이 됨 | PR이 쌓여 승인 대기 | 승인 요청은 하루 한 번 묶어서, 오전 10분 검토 습관 |
| 도구 변화 | 예약 작업 등은 아직 연구 미리보기 단계 | 특정 도구에 종속되지 않게 규칙은 저장소 문서에, 검증은 표준 CI에 |
